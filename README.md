# github-actions-common

Shared GitHub Actions workflows, composite actions, and configuration presets.

## Contents

- Reusable workflows under `.github/workflows/`
- This repository's own workflow entrypoints under `.github/workflows/repo-*.yml`
- Composite actions under `actions/`
- Shared Renovate presets under `renovate/`
- Migration notes under `docs/`

## Workflow Layout

GitHub requires both reusable workflows and repository workflows to live directly under `.github/workflows/`.
This repository uses filenames to keep the two roles separate:

- `repo-*.yml` files are entrypoints used by this repository.
- Other workflow files are reusable workflows intended to be called by other repositories.

For example, `repo-autofix.yml` runs in this repository and calls the reusable `autofix.yml` workflow.

## Pinning and Versioning

This repository manages action dependencies with `.github/workflows/actions.lock`, generated by the official [`gh actions-lock`](https://github.com/github/gh-actions-lock) extension. Workflows and the composite action use readable version tags, while the lockfile pins direct and transitive action dependencies to verified commits, including dependencies of `$/actions/setup-toolchain`.

GitHub CLI is versioned in `aqua/aqua.yaml`. To set up the extension locally:

```powershell
gh auth login --hostname github.com
gh extension install github/gh-actions-lock --pin v0.4.1
```

After adding or changing action dependencies, regenerate and verify the lockfile:

```powershell
gh actions-lock
gh actions-lock --verify
```

Commit the generated lockfile with the workflow changes; do not edit it by hand. Dependabot updates the corresponding lockfile entries when it bumps Actions versions. The repository's static-check workflow runs `gh actions-lock --verify` before merge. `gh actions-lock --verify-local` provides an offline coverage check, but does not verify dependency provenance.

This repository also enables `update-actions-lock: true` in `repo-autofix.yml`. The shared `autofix.yml` workflow accepts this optional boolean (default: `false`) to install `gh-actions-lock` v0.4.1 and regenerate the lockfile after the fix command, before autofix.ci captures changes. It preserves existing pins and fails on moved refs instead of automatically accepting them. Generate the initial lockfile locally when adding a workflow: the runner may reject incomplete lock coverage before autofix can start.

Keep the generator's action references together with its lockfile output. Do not change generated tag references back to SHAs: the runner requires lockfile keys to match the exact references, even when both resolve to the same commit. The v0.4.1 verifier does not catch this mismatch in self-repository composite actions. Local checks require lockfile-aware versions of zizmor (1.32.0+) and ghalint (1.6.0+), managed in `aqua/aqua.yaml`. zizmor 1.32 does not recognize workflow lockfiles when auditing standalone composite action definitions, so only the five covered references in `actions/setup-toolchain/action.yml` have inline `unpinned-uses` ignores.

The composite-action tag references and inline ignores are temporary workarounds for [gh-actions-lock issue #264](https://github.com/github/gh-actions-lock/issues/264). When a released generator preserves composite-action SHA pins, update the pinned extension version in CI and these setup instructions, restore SHA references in `actions/setup-toolchain/action.yml`, and remove its five `zizmor: ignore[unpinned-uses]` comments. Regenerate with the fixed tool without hand-editing the lockfile, then run the required local checks and confirm the PR workflows succeed on GitHub before merging. Keep workflow dependencies managed by the lockfile.

Lockfiles do not pin external reusable workflow calls (`jobs.<job_id>.uses`). A shared workflow uses the lockfile from the repository where it is defined. Callers that use this repository's composite action directly must generate and commit their own lockfile to pin its transitive dependencies; pinning the outer composite action to a SHA alone does not pin the tags inside it.

For security-sensitive workflows, callers should pin reusable workflows and composite actions to a reviewed commit SHA:

```yaml
uses: watanabe-1/github-actions-common/.github/workflows/gha-static-check.yml@<commit-sha>
```

The stable major tag remains available as the official convenience reference:

```yaml
uses: watanabe-1/github-actions-common/.github/workflows/gha-static-check.yml@v1
```

`v1` is a moving major tag. It points to the latest backward-compatible v1 release. Breaking changes must use a new major tag such as `v2`.

Use `@v1` when automatic backward-compatible updates are preferred. Use a commit SHA when reviewability and reproducibility are more important than automatic updates.

## GHA Static Checks

Caller workflow example:

```yaml
name: GHA static checks

on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

permissions: {}

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  gha-static-check:
    uses: watanabe-1/github-actions-common/.github/workflows/gha-static-check.yml@<commit-sha>
    permissions:
      contents: read
      checks: write
      pull-requests: write
      actions: read
    with:
      actionlint-self-action-path: "$/.github/actions/setup-toolchain"
```

If a caller repository still has self-repository reusable workflow calls, pass one representative workflow path to the actionlint compatibility probe:

```yaml
    with:
      actionlint-self-action-path: "$/.github/actions/setup-toolchain"
      actionlint-self-reusable-workflow-path: "$/.github/workflows/add-version-to-pr-title.yml"
```

Use `actionlint-self-action-path: "$/.github/actions/setup-toolchain"` while the caller workflow still references the caller repository's local composite action.
After the caller workflow migrates to this repository's shared composite action, use the default `actionlint-self-action-path: "$/actions/setup-toolchain"`.

## Setup Toolchain

Composite action example:

```yaml
- name: Setup toolchain
  uses: watanabe-1/github-actions-common/actions/setup-toolchain@<commit-sha>
  with:
    setup-aqua: "true"
    node-version: aqua
    bun-version: aqua
    bun-cache: "true"
```

The action resolves `node-version: aqua` and `bun-version: aqua` from the caller repository's `aqua/aqua.yaml`.

## Shared PR Automation

Caller workflows keep their own triggers and permissions, then call the shared workflow from a single job.

```yaml
name: autofix.ci

on:
  pull_request:

permissions: {}

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  autofix:
    uses: watanabe-1/github-actions-common/.github/workflows/autofix.yml@<commit-sha>
    permissions:
      contents: write
      pull-requests: write
    with:
      fix-command: bun run check:fix
```

`autofix.yml` installs dependencies in the repository root before running the fix command. By default, `bun-install-mode: auto` preserves the existing behavior: Dependabot PRs run `bun install`, and other PRs run `bun install --frozen-lockfile`. Callers that intentionally let autofix update `bun.lock` can pass `bun-install-mode: update`; use `frozen` to always require the lockfile to be current, or `skip` to avoid installing.

```yaml
name: Auto Approve

on:
  pull_request:
    types:
      - opened
      - reopened
      - synchronize
      - ready_for_review

permissions: {}

jobs:
  approve:
    uses: watanabe-1/github-actions-common/.github/workflows/pr-auto-approve.yml@<commit-sha>
    permissions:
      pull-requests: write
```

Use the same thin-caller pattern for `pr-labeler.yml`, `renovate-auto-approve.yml`, and `dependabot-auto-merge.yml`.
For `pull_request_target` callers, keep the trigger and dangerous-trigger rationale comment in the caller repository.

`autofix.yml` executes `fix-command` as shell. Keep it as a reviewed literal in the caller workflow, and do not build it from issue, PR, branch, label, or other event data. Pass an empty string to skip the fix command.

## Renovate Preset

Shared default preset:

```json
{
  "extends": ["github>watanabe-1/github-actions-common//renovate/default.json#v1"]
}
```

Renovate presets may use `#v1` when callers intentionally want shared preset updates. Use an immutable tag or commit SHA if Renovate configuration must be fixed for audit purposes.

If this repository is private, Renovate may need credentials that can read it.

```powershell
actionlint
zizmor --no-config .
ghalint run
bun run diff2prompt --lines=20 --exclude=node_modules --exclude=generated-prompt.txt
```
